## User's decision, implementation interpretation and conflicts

The user explicitly requests **1:1 observable Droid Script ability**, including file editing, command execution, test runs, controlled mutations, asynchronous Script lifecycle, and closing the rest of the post-PR-264 gaps, while prioritizing OpenAI/Codex subscription efficiency. Build independently equivalent observable behavior; **do not transplant proprietary implementation, binaries, prompts, private service flags, or circumvent entitlements**. Preserve stronger DaVinci authority checks. “1:1” does **not** mean identical binary layout, permissions bypass, hidden Factory backend, or identical measured performance without matched evidence.

The repo's 2026-10-31 gap plan v2 (`docs/superpowers/plans/2026-10-31-droid-gap.md`) is expressly *measure-first* and says W3 is conditional. Stage 0 **satisfied W3's request-count trigger**; this amendment requests proceeding with a controlled, opt-in parity program. The **existing 2026-10-04 Codemode plan explicitly forbids persistent Script resumption / resident service**, and its execution record says C07/C08 are partial. Full Droid background parity conflicts with those earlier constraints. **Do not silently ignore them:** obtain product/owner approval of this specific amendment before implementing persistent run handles. Keep background opt-in and do not resume guest JavaScript after a hard crash; instead reconcile durable effects and return an honest terminal/stalled status. This achieves the important observable safety/recovery behavior while marking exact post-crash JS resumption as a separately gated research item.

## Approaches considered

1. **Port Droid's runtime literally:** rejected. No permission to reuse proprietary source, breaks Rust ownership, adds Bun dependency, increases disk/RAM, not needed for external parity.
2. **Rely entirely on hosted OpenAI Programmatic Tool Calling:** rejected as an unconditional solution; the `openai-codex` subscription backend has rejected some public Responses shapes. Hosted JS execution only works where live route capabilities permit it. It would not automatically provide DaVinci-owned background handles/durable logs.
3. **Chosen: extend existing Rust-owned Codemode + proven route-specific optimizations.** Use current standalone Node 24.21.0 + QuickJS/WASI sandbox and Rust broker. Add controlled effects, Droid-like Script language surface, per-run evidence, and bounded background handles. Probe hosted/freeform wire variants **separately**, never claim Codex support from public docs. Preserve function tool fallback and direct mode. Reuse existing jobs/process supervisor and operation journal rather than creating competing managers.

## Functional contract — execute Script and mutate safely

- **Modes:** `off`, `read-only`, `controlled`; configurable only by a trusted user/host setting or explicit CLI override; optional `auto` chooses controlled Script only for an admitted route/model and an evaluated task class. A code string can NEVER activate controlled mode. Default remains `off`/current direct until promotion gate.
- **Tool names:** inside JS, support `tools.Read`, `tools.Grep`, `tools.Glob`, `tools.LS`, `tools.Execute`, `tools.ApplyPatch`, plus other explicitly authorized catalog entries, as versioned aliases over DaVinci's existing tools. Native DaVinci spellings stay available. Alias mapping must be collision checked and documented; never synthesize a grant. `tools.Execute` uses DaVinci's ordinary guarded execution path (not a raw Node subprocess).
- **Sandbox:** fresh JS evaluation; top-level `await`, `Promise.all`/`allSettled`, loops and conditions, separate interpreter process; no import, require, direct disk/network/process, host credentials or hidden objects. Expose only frozen `tools`, `inputs`, `text`, `image` when safe, `notify` and bounded console capture. Inputs and outputs cannot smuggle host-origin authority.
- **Script input format:** accept exact multiline `// @input: name <<'TAG'` blocks and `// @script: {"startInBackground":true}` in initial directive region; consume line-exact UTF-8, stable trailing newline semantics, reject duplicate, malformed, missing end markers and duplicate JS aliases. Compatibility should be proved against the supplied Droid mock fixtures, not guessed. Keep legacy `{code: ...}` API while enabling freeform custom `Script` **only when the subscribed backend accepts it**.
- **Tool results:** guest gets typed results `{text, structuredContent, complete, operationRef}` plus structured command metadata (`exitCode`, status, cwd, capped stdout/stderr, duration) through a versioned adapter. `text()`, `image()`, `notify()` are the only explicit visible Script output channels; arbitrary nested results remain in JS. **Never falsely label a truncated result complete**. Image support is required for eventual full output-surface parity and must use a trusted bounded image processing path; until supported and validated, fail clearly and mark that item an OPEN parity gap rather than pretending parity.
- **Authorization:** on EVERY child call, Rust rechecks allowed tool, current permission revision, workspace boundary, symlinks/reparse points, declared effects, specific tool args, root deadline, user approvals and cancellation; use the same `Agent::dispatch_script_child` journal path as direct effects. Potentially destructive Execute commands require ordinary risk classification/approval; no invented `riskLevel` semantic bypass. File edits and tests are not inherently safe based on tool names.
- **Scheduling:** independent reads can run concurrently; disjoint mutating operations only where actual operation policy, file ownership and ordered recovery allow it. Shared writers, dependent read-after-write, test-after-edit, and ambiguous external side effects must serialize/await. No unawaited mutation can be treated as success. Use root budget, bounded in-flight calls, pending calls, output frames and global backpressure.
- **Evidence:** all tool children have stable call id, operation id, effect/outcome classification, status and link to parent script. A script exception after a successful edit does NOT undo the edit, and must say so. A killed/abandoned/unknown mutation does NOT auto-replay. Persist safe and scrubbed results so the model can inspect errors without re-running tests, subject to retention/size caps.
- **Background:** `Script` returns `running` with an opaque `toolCallId` before deadline; `WaitForScript` supports `status`, `wait` and `kill`. Waiting is bounded and cancellation-aware. `// @script` launches detached when approved. `notify()` creates a durable bounded wakeup, delivered once, including across UI reconnect. Crash reconciliation must mark uncertain writes `RECOVERY_REQUIRED`/`STALLED`, never resume speculative guest computation. A background handle cannot outlive its permitted session/workspace/policy lease unchecked. Explicit ownership and kill-on-session-close unless retention/reconnect authority exists.
- **Limits:** preserve current default script 64 KiB, 60s, 64 MiB heap, 64 child calls, parallelism 4, 16 KiB visible output, and 1 MiB guest collected output until stress benchmarks justify changing them. Droid's 1.0 reference reports a different profile (128 in flight, 1 MiB nested aggregate input, 5 MiB visible output, 1,024 events, up to 300s waits, account-variable limits). Treat this as a version-specific compatibility *target* with per-profile ceilings, not an unsafe automatic default. Raise only with measured RSS, memory safety, worker exhaustion and recovery tests.
- **Compatibility:** preserve direct tools, existing sessions, JSON function `codemode` callers, UI/CLI/SDK APIs, existing permission prompts, Windows-native support and Linux/macOS. No Node requirement when Codemode is off. A native custom wire kind must be recorded and replayed without rewriting prior prefix/tool history.

## OpenAI caching and prompt contract

- Maintain stable `openai-codex` request prefix and session key; tool catalogs may not change unexpectedly. Log *exact* cache identity and segment fingerprints (trusted instructions, tool schema, conversation append, dynamic context, model/settings, provider route). Correlate with actual provider cached/un-cached numbers and bytes without storing secrets.
- Reproduce the PR #264's 16 mid-session cache drops. Classify (prefix divergence, provider cache miss/eviction/routing, schema reordering, model/effort change, unsupported replay, unknown). Retain `UNKNOWN` when no causal evidence.
- Avoid overhead regressions: Script contract, tool-binding reference and deferred tool inventories must fit into the first-request budget; only show bindings relevant to current mode and authorized tool set. Stage 0 did **not** establish a smaller initial prompt as an advantage over Droid, so smaller is not an unconditional goal.
- Test native `custom` freeform, `programmatic_tool_calling`, `tool_search`/`defer_loading`, `additional_tools` **only on the exact Codex route with explicit bounded authorization**. Public API acceptance is not proof. Preserve a function-typed script fallback when rejected. When native hosted PTC is supported, app-side mutation checks and audit stay mandatory.
- For cache TTL/breakpoints, use route capability detection; never blindly send `prompt_cache_options.ttl`/explicit breakpoints through the subscription websocket. Model-specific public API economics (write costs) do not establish subscription-account quota accounting.
- Default Context VM `off`; maintain append-only native items until threshold, and compare hybrid vs off vs active in independent long-context tests. Never enable hybrid merely to increase cache-hit percentage. No compaction changes without a tested failure/cost case.

## Outcome metrics and acceptance

**Behavioral parity:** all applicable deterministic Droid fixtures 01–12 (from supplied reference) pass with correct Script/direct semantics; a real detached Script test uses `wait/status/kill`, `text` and error output survive a restart, and mutation authorization + recovery remain safe. Strong independent security regression coverage includes forced crash at before-journal, after-permission-before-effect, after-effect-before-resolution, after-journal, and after-owner-reconnect points.

**Performance:** one repetition on 17 tasks is a pilot, not proof of parity. Run matched immutable tasks with independent grading, three modes (`davinci-direct`, `davinci-controlled-script`, `droid-script`) and consistent model/effort; report all failed/unfinished attempts. PR #264's comparison to Droid is `product-system` because Droid uses CLIProxyAPI and DaVinci uses native WebSocket. No causal claim until transport confounds addressed or explicitly bounded. For official performance parity use repo competitor gate (>=150 scenarios, three repetitions, confidence/noninferiority and no safety regressions).

**Primary optimization objective:** *verified completed tasks / actual subscription usage* where account usage observation exists. Proxy counters and list-price estimates must remain secondary estimates; cached tokens count toward model context and token-per-minute. An improvement in total input or request count without an improvement in actual allowance or success is **request efficiency only**, not proven subscription longevity.

**Release gates:** no unauthorized mutation; no duplicate or ambiguous side-effect replay; zero stuck/unowned background workers; zero leaked secrets; 100% deterministic fixture correctness; history replay mode stability; retained direct-mode pass rate; no degradation on access revocation, cancellation, controls or account-prohibited features. Enable controlled mode only after C08 recovery matrix and core CI pass, then opt-in, then A/B and narrowly-scoped default promotion. Archive failure cases and rollback instructions.

## Five high-risk review inputs

1. A controlled Script discovers a writable capability, then the user revokes permission **while it is queued**: must deny before side effect.
2. A script patches a file successfully, then JS throws or the Node host crashes: file remains changed, journal notes successful effect and script failed/partial; no replay.
3. The user kills a Script while a shell command has spawned child processes: cancel the entire owned process tree or mark unresolved honestly; no orphan effect or false `cancelled` claim.
4. A Script started on session A is polled under session B or after workspace/branch switch: no cross-session data access; handles are scoped, authenticated to host-owned identity.
5. A cache-miss event occurs after no wire change: report provider-side/unknown classification, not fabricated local prefix break; preserve unmatched usage as missing.
