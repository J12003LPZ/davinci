# V1: verification recognition and completion

Status: accepted as a deterministic repair, with latency and model-variance
concerns documented below. The complete screen passed 24/24 DaVinci cases,
matched the parent's 24/24, and reduced requests and reminders. Earlier
interrupted campaigns and both diagnostic A/Bs remain part of the evidence.
See [duration A/B](V1-duration-ab.md) and [CSV A/B](V1-csv-ab.md).

## Changes

- Inspect bounded Python ASTs in an isolated interpreter without executing or
  importing the inspected source. Recognize assertions, bounded case tables,
  expected exceptions, literal unittest cases, local check helpers and subprocess
  output assertions. Print-only diagnostics, optimized assertions, masked shell
  chains and unsupported syntax remain inconclusive.
- Require original terminal process evidence. Capture the mutation generation
  immediately before dispatch; journal replay cannot create fresh evidence.
  Direct calls and batch children share the same verification observer.
- Accumulate targeted coverage within one generation, retain outstanding paths
  after partial checks, and invalidate coverage after another mutation. Include
  directly imported changed modules and their unconditional local imports;
  recognize test/documentation exemptions only alongside applicable coverage.
- Distinguish partial, missing and failed verification. Partial checks do not
  force another model request. Final host notices disclose unresolved evidence.
  Automatic verification retains saved arguments/cwd and normal authorization.
- Keep transaction verification and permission classifiers unchanged. The
  existing literal shell tokenizer is shared without expanding execution policy.
