# C1 — effective prompt-cache identity

Status: accepted source correction; a new live promotion campaign is still
required before attributing provider-cache gains to this change.

Task 11 audited the bytes represented by the cache identity. The previous
system-prompt helper returned the prompt manifest's stable module hash even
when the provider request included repository context, provider suffixes, or a
request-local system append. C1 now hashes the effective provider-visible
instruction string. The manifest remains available for diagnostics, but it no
longer replaces the bytes sent to the provider.

The cache construction in `davinci-coding-agent` now derives the tool identity
from the resolved Responses wire tools. That includes custom apply-patch
grammar text, grammar version, strict/constrained-sampling metadata, and the
actual function schema. Non-Responses adapters hash the complete serialized
`ToolSpec` contract. The same tool vector is passed to the request and to the
identity calculation, preventing a request/identity mismatch.

The identity tests cover appended instructions, provider-visible project paths,
transient run metadata, Context VM lineage, permission changes, and the
resolved Responses schema. Context VM affinity remains part of the identity;
the correction does not weaken recovery invalidation or transport isolation.

The cache report now emits deterministic hashes for the complete logical and
wire request bodies plus instructions, tools, and input. It also reports
whether the first observed request had zero cached input. Archived logical
request files for the September campaign were not retained in the evidence
directory, so a new first-request-zero denominator cannot be reconstructed
from those files. The earlier wire diagnosis shows the first requests already
had nonzero cached input (roughly 8.7k tokens); that is observed cache reuse,
not proof that a fresh workspace starts cold.

No-session transport remains an independent in-memory session, and durable
session/native-resume validation is unchanged. The C1 source fix therefore
corrects the proven identity gaps without claiming provider-side cache
availability or cross-conversation reuse.
