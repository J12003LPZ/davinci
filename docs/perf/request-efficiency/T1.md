# T1 - Fast service-tier arm

Status: measured screening arm; no default service-tier change.

Product control: `/fast` selects priority routing for the existing Codex OAuth
model, and `/status` shows the requested mode. User settings `serviceTier: "fast"`
or `DAVINCI_OPENAI_SERVICE_TIER=fast` initialize the session (environment wins).
Standard remains the default. Explicit backend tier mismatches are reported;
missing returned tier metadata is unknown. This integration adds no new live
benchmark evidence or subscription savings claim.

Task 10B ran the Fast service tier as a separate fixed-policy arm on both
harnesses. The arm used the same G1 binary, fixture, model, medium effort,
stable prompt profile, full tool surface, and `reasoningSummary=auto` as the
default-tier S1 campaign. The runner passed the requested tier explicitly to
both harnesses and recorded the effective tier in each result row. The Fast
arm is kept separate from default-tier comparisons; its metrics are diagnostic
and do not establish a default promotion.

## Cost and failure observations

DaVinci provider observations included cost objects on 138 completed attempts.
The Fast arm recorded total provider-attempt cost `0.04002004` in the captured
telemetry; the default S1 control recorded `0.04161852` over 148 attempts.
Codex turn-completion telemetry recorded token usage but no cost object. The
cost values are raw captured telemetry, not an invoice or a normalized price
comparison.

DaVinci passed 21/24 rows: all three `t2-duration` repetitions failed. Codex
passed 21/24 rows: `t2-duration` repetition 0, `t5-csv` repetition 2, and
`t6-bookings` repetition 2 failed. These task-level differences and the small
three-repetition sample do not justify changing the default service tier.

## Decision

Keep the default service tier unchanged. Retain the Fast campaign as the
measured Task 10B evidence, with latency and provider-cost telemetry recorded,
and keep rate-limit behavior explicitly unverified. Any future tier decision
needs a larger, separately pinned campaign with a predeclared correctness and
cost threshold; it must continue to keep Fast and default rows out of the same
parity comparison.
