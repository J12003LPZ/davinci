## What this shows

- **Each mode is the one the model ran with.** `harness_stats` reported the
  configured Context VM and Codemode mode in every run.
- **Codemode is used when it is on.** 6 and 3 calls on the coding task, 4 of 6
  survey sessions, with answers above the correctness gate. Before today,
  recorded runs showed 0 calls (`docs/codemode.md`).
- **Context VM folds only when context reaches the threshold.** At 40k, no
  request on this task got there (peak 21.6k), so hybrid and active behaved like
  off: 0 folds, `retrieve_context` never offered. At 14k both folded (15 and
  25 folds) and offered `retrieve_context`; the model never called it.
- **Folding at 14k cost more than it saved on this task.** Fold summarizer
  requests (13 and 22) read no cache, cache share fell to 78% (hybrid) and 41%
  (active), and wall time rose to 187 s and 269 s against 63 to 85 s
  unfolded. The largest coding request did not shrink (20.5k hybrid, 29.6k
  active, against 18.9k to 21.6k unfolded), and the cumulative fold counters
  report `tokensAfterFold` above `tokensBeforeFold` (25,029 > 24,002 hybrid;
  37,950 > 36,556 active). Those counters are checkpoint-ledger size estimates
  summed over folds, not provider prompt sizes, so they do not show that folds
  enlarge the context. The provider logs explain the growth: in the hybrid arm
  no compaction was ever applied (`runtime.compactions` 0 next to 15 folds), so
  the coding prompt grew with the conversation (14,843 to 20,497 tokens) while
  13 summarizer requests were paid for and discarded. Prompt size is measured
  by `hybridCompaction.contextTokensBefore/After` (applied compactions, message
  estimates) and `scripts/bench/fold_economics.py`; see
  `hybrid-fold-economics.md`.
- **The task outcome did not depend on the mode.** Every arm passed 5 of 6
  hidden tests, the same one failing in all of them, so no arm is a fully
  verified success. One rep per arm on a tuned task is direction only.
- **The 14k arms are not a controlled comparison.** They used threshold 14,000
  (keep 3,000, reserve 3,000); the five other arms used 40,000 (keep 8,000,
  reserve 8,000). Cost, cache share and wall-time differences between them mix
  the mode with the compaction settings.

Decision for Task 8 (mode default): keep `contextVm` off by default. Nothing
here supports a Hybrid or Active default; a controlled A/B (same compaction
settings in every arm, tasks that reach the threshold) must come first.
