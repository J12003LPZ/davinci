## Context VM and Codemode use

Both are chosen in `/config` and the model works with whichever mode is set:
Context VM `off`, `hybrid` or `active` (`shadow` is diagnostic), Codemode `off`
or on (`read-only`). The owner's `~/.davinci/agent/settings.json` has
`contextVm: "off"` and `codemode: {"mode": "read-only"}` (read today).

Before `68f25643` no run log could show either feature at work: `harness_stats`
carried only `RunStats`, and bench `effective_settings` lacked both keys unless
the settings file set them. Historical evidence, read from logs today:

- 14 campaigns under `C:\bench` ran with `contextVm` active or hybrid. None shows
  a fold, a `retrieve_context` call or a compaction. The tasks never grew long
  enough to fold, and `retrieve_context` is only offered after a fold
  (`crates/davinci-agent/src/lib.rs`, `context_vm_offers_retrieval`).
- No `codemode` tool event appears in the 24 October 17 runs or in the 36 runs
  of `luna-high-recovery-03\vm-active-cm-on` (Codemode read-only). Those logs
  carry no `harness_stats` codemode record, and tool events can show use but not
  its absence, so bench `feature_use` reports that arm as `unknown`, not
  `configured_but_unused`. A confirmed zero needs the `codemode.calls` record.

From `68f25643` on, `harness_stats` reports `contextVm` (mode, fold, page and
retrieval counters, `retrievalOffered`) and `codemode` (mode, `available`,
`calls`) per run. Bench summaries take the mode from that record (`observed_mode`),
keep the settings' request apart (`requested_mode`), list runs where the two
differ (`mode_match`), and flag a mode with no activity only on a confirmed zero
(`no_folds_observed`, `no_calls_observed`); a run without the record is
`unknown`.
Whether the model uses each mode on real tasks needs a live run per mode; none
has been made with the new fields.
